# 次世代鋳造CAE「RX-CAST」構想・技術設計書

## 1. プロジェクト概要

### 製品コンセプト

- **製品名：** **RX-CAST**（アールエックス・キャスト）
- **名称の由来：**
  **R**eal-time e**X**ascale **C**omputational **A**I **S**olidification **T**win
- **意味：** リアルタイム・エクサスケール対応のAI凝固デジタルツイン
- **コアコンセプト：** **ノーメッシング × GPUネイティブ高速演算 × Physics-AI統合**

本設計書は `docs/reviews/review-from-chatgpt-01.md` の指摘を反映し、LBM/AMR、自由表面と気相、凝固連成、V&V、サロゲート、ロードマップのリスクを明示的な成立性ゲートと仕様へ変更しています。
「Exascale」はブランド名としての由来とし、初期製品の単一GPU性能をExascale相当と主張しません。実測対象はハードウェア構成ごとのスループット、メモリ、Time-to-Accuracyとします。

### ターゲット市場

主なターゲットは、高圧ダイカストの大型・薄肉・複雑リブ形状部品、特にEV用ギガキャストです。既存CAEの以下の課題を解消することを狙います。

- メッシュ作成と形状修復にかかる膨大な工数
- 大規模均一格子によるセル数爆発と長い計算時間
- 設計案ごとの試行錯誤に伴う解析待ち時間

砂型鋳造や既存方式で十分対応できる領域より、既存ソルバーが苦手とする超大規模・高速充填・複雑薄肉形状に一点突破します。

### 初期Operating Envelope

Phase 0開始前に、以下の範囲を初期値として固定し、実験または顧客データで承認します。

| 項目     | 初期値または要求形式                                                                       |
| :------- | :----------------------------------------------------------------------------------------- |
| 材料     | 単一アルミ合金を対象とし、組成、温度依存熱物性、粘性、密度、潜熱、固相率曲線を指定         |
| 幾何     | 最大鋳造寸法、湯口・流路・最小肉厚、最小解像セル幅、肉厚あたりの最低セル数を指定           |

| 現象     | 初期対象は湯先到達、未充填、充填形状、温度履歴。酸化膜、溶存ガス、金型変形は段階的に対象化 |
| 計算環境 | 対象GPU、VRAM上限、許容メモリ、単一GPUまたはマルチGPU、許容解析時間を指定                  |
| 精度     | 湯先到達時間、充填形状、温度、欠陥位置の評価量ごとに誤差目標を実験不確かさと併せて承認     |

## 2. 市場ポジショニング

既存の主要商用CAEは豊富な物性DBや実績を持つ一方、CPU中心の陰的FVM/FEMや均一格子に起因するスケーラビリティの壁があります。

| 比較項目         | 既存ハイエンドツール群                                              | RX-CAST                                                              |
| :--------------- | :------------------------------------------------------------------ | :------------------------------------------------------------------- |
| 計算基盤         | CPU主軸。一部はGPU高速化モードを持つが疎行列解法などがボトルネック  | GPUネイティブ実行を設計し、方式ごとの検証済みアルゴリズムを採用      |
| 空間離散化       | 均一格子、直交格子、または非構造FEM。メッシュ作成やセル数増大が課題 | 検証後に静的/動的AMRまたはブロック構造AMRを選定                      |
| 湯流れ・自由表面 | 多くはVOF法。圧力ポアソン方程式の反復が重い                         | LBM・GPU-FVM・VOFを比較し、精度・安定性・性能で選定                  |
| 凝固・熱応力     | FEMはメッシュ作成、直交格子系は曲面・応力精度に課題                 | 陽的・局所陰的エンタルピー法と、物理に適合するFEM方式を選択          |
| 組織・欠陥予測   | Niyama基準が中心。一部でCAFE等を提供                                | GPU並列CAによる結晶組織予測と改良欠陥指標                            |
| AI・設計探索     | 外部連携や多数ケースのDoE・最適化が中心                             | 工程条件サロゲートから段階的に拡張し、信頼区間とフォールバックを提供 |

### 差別化ポイント

1. **検証済みGPUネイティブ解析による設計反復の高速化**
   Phase 0でLBM、GPU-FVM＋VOF、AMR方式を同一条件で比較し、同等精度を維持した解析時間の短縮を実測します。
2. **共通幾何・場データ基盤による一気通貫解析**
   流体、伝熱、応力、組織予測は共有する幾何表現、領域、場交換基盤を用意し、各物理の離散化は独立に選択します。
3. **信頼性を明示したリアルタイム設計探索**
   工程条件変更から段階的にサロゲートを構築し、学習範囲、予測不確かさ、追加CAE解析へのフォールバックを提供します。

## 3. 物理モデリングと連成戦略

### 完全強連成を採用しない理由

流体、凝固、接触弾塑性を単一の巨大行列で解く完全強連成は、次の点から実用ソルバーとしてのリスクが高いものとします。

- 湯流れは $10^{-5}$ 秒オーダー、凝固・冷却は1秒以上の時間スケールに分かれる
- 流体に適したオイラー格子と変形に適したラグランジュ格子を共存させにくい
- 非線形性の異なる現象を一体化すると反復計算の収束が悪化する

### フェーズ分割と局所的陰的連成

#### フェーズ1：充填期

- 流動と対流伝熱は選定済みの自由表面流体スキームと熱輸送スキームで計算
- 固相率 $f_s$ を用いて運動量損失を与え、Carman-Kozeny式／ダルシー則で流動停止を近似
- 充填中は応力変形を無視し、湯流れと熱伝導の計算に集中

#### フェーズ2：充填直後の高圧保持

- 射出・増圧・保持圧履歴は、プランジャーまたは流入口に対する圧力・速度・荷重境界条件として与える
- 固液共存域では、固相率に基づく透過率またはDarcy抵抗を用いて流動抵抗を計算する
- 液相の連結性、ゲート凝固、圧力伝播の遮断を考慮し、保持圧がキャビティ内へ伝わる経路を追跡する
- 等価体積力を簡略化として使う場合は、その導出、適用範囲、妥当性を別途検証する
- 自由表面が消失した領域では流動と凝固収縮を連成し、必要な給湯・ポロシティ源を計算

#### フェーズ3：凝固・冷却期

- 解法切替は単独セルではなく、連結液相領域または計算ブロック単位で管理する
- 状態遷移は `Active Flow → Reduced Flow → Thermal Only` とし、Reduced Flowでは給湯・圧力伝播を縮約モデルで維持する
- 再活性化条件、状態間の保存量の引継ぎ、ヒステリシスを定義し、閾値付近での頻繁な切替を禁止する
- 液相率、圧力勾配、残留速度、連結液相領域は複合判定に用いる。速度ゼロのみを停止条件にしない
- 速度向上が十分でない場合は、自動停止ではなくフロー計算を継続する選択肢を残す
- エンタルピー法で伝熱・凝固・潜熱を計算し、完全凝固後は冷却と熱応力へ移行
- エアギャップは熱伝達と構造変位の双方向連成で扱う

エアギャップの更新は、同じ時間ステップ内で次のサブ反復を行います。

1. 伝熱計算
2. 応力・変位計算
3. ギャップ幅からIHTCを更新
4. 熱を再計算

緩和係数、最大反復回数、温度・ギャップ幅・熱流束の収束条件、ステップ縮小、界面熱流束保存を明示します。解法切替の閾値はダムブレイク、鋳造実験、固液連成ベンチマークで決定します。

## 4. 技術スタックとソフトウェアアーキテクチャ

### コア計算基盤

- **開発言語：** C++20
- **並列基盤：** CUDA、将来のマルチGPU拡張にNCCL／MPIを併用
- **アルゴリズム：** 局所演算と陽的ステップを中心にし、GPUのSIMT並列性能を活用
- **空間離散化：** 静的AMRで検証後、必要性と性能が確認できれば動的ブロック構造AMRへ拡張

従来のSIMPLE法や陰的FVMは、巨大な疎行列と圧力ポアソン方程式を反復解く必要があり、GPUのメモリ帯域と同期オーバーヘッドがボトルネックになりやすいものです。LBMが選定された場合は衝突・並進、FVMが選定された場合は陽的または局所反復による流束更新など、GPU上のローカル演算を方式ごとに主体とします。ワークステーション1台のハイエンドGPUで、従来のCPUクラスタに対する桁違いではなく実測可能な高速化を目標とし、マルチGPU展開はNCCL／MPIで段階的に行います。

### RX-Flow：湯流れエンジン

- **技術選定：** Phase 0ではLevel 1でLBM系とGPU-FVM＋VOF系を比較し、合格方式についてLevel 2で衝突・界面・AMR・メモリ配置を最適化する
- **自由表面：** 液相体積、湯先、界面を追跡し、閉じ込め気泡の識別・圧縮・分裂・合体、ベント/真空条件を段階的に追加
- **AMR候補：** まず規則ブロックを内部に持つブロック構造AMRを優先し、粗細補間、時間スケーリング、保存則、再分割コストを検証
- **境界条件：** 壁面、入口、出口、プランジャーの境界処理を方式ごとに定義する。LBMではImmersed Boundary／Bounce-back等、FVMでは埋め込みまたはセル面流束境界を検討する
- **形状処理：** STLを入力し、閉鎖性、自己交差、非多様体、法線、最小肉厚を検査。修復可能性と修復方針を診断してから格子化

LBMは圧力ポアソン反復を不要にし得ますが、低マッハ数、物理粘性、緩和時間、粗細格子、時間刻み、自由表面・気相モデルが成立しなければ採用しません。GPU-FVM＋VOFを含む代替案を撤退可能な技術ゲートとして維持します。

ギガキャストのような大型・薄肉（例：1.5～2mm）部品では、均一格子を使用するとセル数が数億個に達し、メモリと計算時間が破綻します。AMRでは自由表面（湯先）と薄肉壁面付近を優先して静的または動的に細分化し、内部領域では粗いブロックを維持します。初期は静的ブロック構造AMRを優先し、動的再分割は保存則、補間、再配置コストと実測速度を確認して拡張します。

AMR性能は単純なセル更新数ではなく、次式の合計で均一格子と比較します。

\\[
T_{\mathrm{total}}=T_{\mathrm{solve}}+T_{\mathrm{adapt}}+T_{\mathrm{transfer}}+T_{\mathrm{communication}}+T_{\mathrm{I/O}}
\\]

LBMでは分布関数の補間・再構築、FVMでは粗細流束の整合を保存則ごとに検証します。薄肉部品では肉厚あたりの最低セル数をOperating Envelopeで固定し、自由表面だけでなく湯口・狭い流路・壁面の解像度を要求します。

ダイカストの激しい飛沫、プランジャーや中子の移動を主対象とする用途では粒子法（SPH/MPS）も候補です。ただし、凝固収縮時の静水圧、熱境界、長時間安定性の厳密な扱いを検証します。主方式は比較ゲート後に確定し、粒子法は局所補完または将来の代替案として扱います。

自由表面と気相は次の段階的モデル候補を持ちます。

| モデル                 | 初期適用                                         |
| :--------------------- | :----------------------------------------------- |
| 単相流＋自由表面       | 湯先到達、充填形状、未充填領域                   |
| 単相流＋気泡圧縮モデル | 閉じ込め気泡、簡易ベント、初期空気巻き込み       |
| 圧縮性気相を含む二相流 | 排気経路、ゲート通過、ベント背圧、高度な気相解析 |

気相モデルは流体数値方式と一体で評価し、単相自由表面での結果だけを二相・ベントモデルの採用根拠にしません。

### RX-Solid：伝熱・凝固・応力エンジン

- **充填中：** 流体方式に対応する熱輸送スキーム（候補：熱LBMのDouble Distribution FunctionまたはGPU-FVM）で速度場と温度場を計算
- **凝固・冷却中：** 陽的または局所陰的エンタルピー法へ切り替え
- **固相率：** Scheil-Gulliver等のモデルで潜熱と固相率変化を反映
- **応力・変形：** Matrix-FreeボクセルFEMまたはMPMを候補として検討
- **エアギャップ：** 熱伝達と変位の双方向サブ反復

充填完了後も保持圧、凝固収縮、自然対流を考慮し、液相停止の物理的閾値を満たす領域から段階的に熱伝導＋エンタルピー法へ切り替えます。

Matrix-Free FEMは剛性行列の組立を省くだけで線形反復や前処理が不要になる方式ではありません。ボクセル境界の幾何誤差、弾塑性内部変数、接触・剥離、摩擦、温度依存材料特性を考慮し、ボクセルFEM、CutFEM、埋め込み境界FEM、有限セル法を比較します。流体・熱・構造で離散化と自由度配置を分けても、幾何、領域、場データは共通基盤で交換します。

### RX-Solid：ミクロ組織・欠陥予測

- **機能分割：** Thermal/Solidification、Feeding/Shrinkage、Defects、Microstructure、Mechanicsのモジュールに分離
- **技術選定：** マクロ熱場に埋め込むGPU並列セルオートマトン（CA）法
- **組織予測：** 核生成、デンドライト成長、柱状晶から等軸晶への遷移（CET）
- **欠陥予測：** 欠陥機構ごとに別モデルを保持する。収縮ポロシティ、ガスポロシティ、湯境、コールドシャット、酸化膜巻込、熱間割れを区分
- **機械的特性：** 結晶粒組織予測結果を局所特性へ接続

従来のNiyama基準は手早く欠陥リスクを評価できる一方、最新合金や薄肉ダイカストの微細組織までは直接予測できません。ProCASTのCAFEモジュール等で実現される結晶粒成長の直接予測は精度面で有効ですが、計算が重い場合があります。

マクロ格子内に細分化セルを持つCA法は、核生成や成長方向をローカルルールとして並列更新できるためGPUとの親和性が高いものです。この機能により「高速解析とミクロ組織・機械的特性予測」を標準搭載し、競合ソルバーに対する差別化ポイントにします。

収縮ポロシティでは密度変化、液相・固相の相変化、給湯経路、ゲート凝固、圧力伝播を扱います。ガスポロシティでは閉じ込め気体、溶存ガス、気泡圧縮、核生成を別状態として扱います。酸化膜巻込みには自由表面履歴と界面折り込み履歴を使い、湯境・コールドシャットには合流時間と温度履歴を使います。Scheil-Gulliver等の固相率モデルは適用合金、状態図、拡散仮定、固相率曲線とエンタルピーの整合性を仕様化します。

### RX-Twin：Physics-AI

解析が数倍速いだけでは既存ソルバーからの置換理由になりにくいため、CAEソルバーをAIの教師データ生成器として製品へ統合します。最初は同じ形状・工程条件範囲を対象に、低次元入出力のサロゲートで開始します。

1. **自動デザイン探索（Headless Batch）：** 固定形状で射出速度、温度、保持圧等を変え、GPUソルバーを夜間に数百ケース実行。ゲート形状変更はこのフェーズの対象外とする
2. **オンデマンド学習：** 温度場、流速場、欠陥位置、組織場の3D結果をGNNまたはFNOで自動学習
3. **リアルタイム設計：** 固定形状・工程条件サロゲートで、CAD変更を含む段階へ拡張し、エンドツーエンド0.1秒の目標を検証

業界ではMAGMA等の解析結果を活用したサロゲートモデリングも進展していますが、物理ソルバーとAI学習パイプラインを一体化することで設計現場のワークフローを短縮します。出力の表現、訓練範囲、学習範囲外検出、予測不確かさ、CAEへのフォールバックを仕様に含めます。

「0.1秒」は固定形状の工程条件変更では推論、特徴量生成、データ転送、可視化を含む応答時間とし、CAD形状変更を含む場合は形状処理を含む別の応答時間として計測します。固定形状の工程条件変更を最初の合格対象にします。FNOは規則格子、GNNは不規則形状へ候補を分けても、任意CAD形状への汎化は保証しません。

### ソフトウェア構成・UX

- **完全ヘッドレス＆Python APIファースト：** ソルバーコアをGUIから分離し、CLI／Python APIとして提供
- **操作のスクリプト化：** STL投入、条件設定、実行、結果抽出をPythonで記述可能
- **自動化連携：** 顧客の最適化・パラメトリック設計パイプラインへ組込み可能
- **モダン可視化：** C++／Qtの重厚なデスクトップUIではなくWebGPUまたは軽量なモダン3Dエンジンを採用
- **クラウド可視化：** クラウドGPUで計算した数億セル規模の結果を、ブラウザ上で軽量に確認

重厚なデスクトップGUIではなく、クラウドGPUで計算しブラウザで可視化する構成を基本とします。

### 共通基盤とソルバー境界

物理モデル間で共有するのはメッシュではなく、幾何表現、空間領域、場データ、I/O、タイムステップ調停です。推奨構造は次のとおりです。

- CLI / Python API / Web UI
- Simulation Orchestrator
- RX-Flow（LBMまたはGPU-FVM）
- RX-Thermal（熱・凝固）
- RX-Mechanics（応力・接触）
- Shared Geometry & Field Infrastructure（SDF、AMR、場マッピング、I/O）
- GPU Runtime（Memory Pool、通信、プロファイリング）

この分離により、流体方式や構造離散化を変更してもジョブ制御と製品インターフェースを維持します。

基盤仕様には、精度ポリシー（FP32、FP64、混合精度）、GPU Memory Pool、SoAレイアウト、メモリ予算、乱数シードと演算順序、決定論性、数値発散・AMR失敗・OOM・入力異常の診断、チェックポイント、再開、結果スキーマ、Kernel時間、帯域、セル更新性能、プロファイリング指標を含めます。

単一GPUでの正確性と性能基準を確立した後にマルチGPUへ拡張します。NCCLとMPIは役割を分け、領域分割、非同期Point-to-Point、GPU Direct、CUDA-aware通信、デッドロック回避を検証対象にします。

## 5. 検証・ベンチマーク計画

鋳造CAEでは、検証目的に応じて実験ベンチマーク、公開シミュレーションケース、プロセスデータ、熱物性データを使い分けます。

### 5.1 物理ソルバー検証用の標準ベンチマーク

#### MCWASPベンチマーク

MCWASP（Modelling of Casting, Welding and Advanced Solidification Processes）では、アルミニウム平板などの湯流れ・凝固・引け巣に関する比較課題が提示されています。論文アーカイブから「MCWASP benchmark casting」を検索し、以下の実験条件を検証ケースへ反映します。

- 鋳型寸法、注湯温度、充填完了時間
- 各測定位置の熱電対温度履歴
- 湯面到達時間、凝固時間、引け巣発生位置
- 合金組成、鋳型材、初期温度、境界伝熱条件

#### 商用CAE公開ベンチマークマニュアル

公開されているAltair Manufacturing SolverのCasting Benchmark Manualなどは、幾何形状、熱電対位置、A356合金等の物性値、実測冷却曲線を論文参照付きで確認できます。商用マニュアルの数値はライセンス条件と参照元を確認して利用し、自作ソルバーの検証ケースとして段階的に再現します。

#### 相変化の基礎ベンチマーク

- **Stefan問題：** 解析解がある1D/2Dの潜熱放出・相変化問題。伝熱とエンタルピー法の基礎検証に使用。
- **ダムブレイク：** 自由表面形状、到達時間、界面保存性の検証に使用。
- **キャビティ自然対流凝固：** Pb-Sn合金またはガリウムを用いた流動＋相変化。Gobinらの実験・論文データを参考にし、自然対流と凝固の連成を検証。
- **円筒型金型＋A356アルミの冷却曲線：** Kronらの研究等を中心に、熱伝達・潜熱・冷却速度を確認。

### 5.2 データ共有プラットフォーム

#### Zenodo、Mendeley Data、GitHub

- 射出速度、ストローク、増圧圧力、品質、温度場等を含むダイカストプロセスデータを代理モデルの教師データ候補にします。
- 「I-BiDaaS - CRF - Aluminium die-casting Synthetic Dataset」等の合成データは、パラメータ範囲、欠損、計測ノイズ、品質ラベルを確認して使用します。
- 論文附属データ、CAD/メッシュ、境界条件、計測結果を含むリポジトリは再現性が高いものから採用します。

#### 放射光In-situ観察データ

SPring-8、Diamond Light Source、ESRFなどで得られた金属凝固のリアルタイム画像や定量データは、Zenodo、IOP、MDPI等で公開される場合があります。主な用途は以下です。

- デンドライト成長速度と凝固前線位置
- 液相の局所流動と組織形成
- 気泡、ポロシティ、引け巣の発生過程
- GPU並列CA法、欠陥予測、時系列画像からの機械学習

#### 鋳造欠陥画像・測定データ

- Kaggleの「Casting product image data」
- Zenodoの「Defect Detection Dataset: Porosities in Machined Aluminum Holes」
- CT画像、外観画像、欠陥座標、欠陥体積を含む公開データ

これらは主に画像認識・外観検査向けですが、CAE予測の欠陥位置や空隙率との照合には利用できます。一方、画像だけから内部欠陥を推定できない点、ラベル定義、撮影条件のばらつきを考慮する必要があります。

### 5.3 熱物性・状態図データ

鋳造CAEでは、液体から固液共存域、固体への遷移に伴う熱伝導率、比熱、潜熱、粘性、密度、熱膨張の温度依存性が必要です。

- **OpenCALPHAD：** 合金組成から液相線温度、固相線温度、Scheil-Gulliver固相率曲線を計算
- **NIST Materials Data Repository：** 金属の熱伝導率、比熱、エンタルピー等の基礎熱物性
- **Materials Project：** 計算データベースとしての補完。生成元、計算条件、測定値との対応を確認して使用

溶湯粘性、界面熱伝達係数、エアギャップIHTC、鋳型接触条件は文献値だけでなく、実験冷却曲線を用いたキャリブレーションで決定します。

### 5.4 オープンソースCAEテストケース

OpenFOAMのチュートリアルは、使用するバージョンと具体的なケース名を固定した相互比較リファレンスとして再利用できます。例として、自由表面流は`interFoam`、相変化・エンタルピーは対応する`solidificationMelting`または公式チュートリアル、凝固・融解時の対流は検証済みの具体的ケース名を使用します。

- 自由表面流：バージョン固定済みの`interFoam`チュートリアル
- 相変化・エンタルピー多孔質体モデル：バージョン固定済みの対応チュートリアル
- 凝固・融解時の対流：バージョン固定済みの具体的ケース

OpenFOAMの数値結果は実験データではないため、厳密解や実測データとの比較を併用し、単独で精度を証明しないようにします。

### 5.5 開発フェーズ別の検証計画

1. **アルゴリズム立上げ：** Stefan問題、ダムブレイク、キャビティ自然対流凝固で伝熱、相変化、自由表面の基礎を確認。
2. **湯流れ検証：** ダムブレイクで自由表面を合わせた後、MCWASPのアルミ板充填実験で湯面到達時間と充填形状を比較。
3. **凝固・冷却検証：** A356等の円筒型金型冷却曲線で潜熱、固相率、IHTCをキャリブレーション。
4. **欠陥検証：** 引け巣、気泡、ボロシティの実測位置または欠陥画像とCAE予測を照合。
5. **組織検証：** 放射光データまたは金属組織画像でCETと結晶粒成長を比較。
6. **AI検証：** 実験データと未知条件を予約し、教師ケースだけでなく汎化性能と再現性を評価。

### 5.6 Verification、Validation、UQ

検証は以下に分離し、合格基準とトレーサビリティを設定します。

- **Code Verification：** Manufactured Solution、保存則、収束次数、厳密解との比較
- **Solution Verification：** 格子収束、時間刻み収束、AMR誤差、丸め誤差
- **Validation：** 湯先到達時刻、熱電対履歴、X線観察、欠陥位置・体積との実験比較
- **Uncertainty Quantification：** 物性値、IHTC、射出速度、計測誤差が予測へ与える不確かさ

最低限のテスト対象は、LBM基本流（Poiseuille、Taylor-Green渦）、AMR流（粗細格子間の質量・運動量保存）、静止液滴・ダムブレイク・閉じ込め気泡、平板熱伝導・移流拡散、Stefan問題、Patch test・熱膨張・片持ち梁、界面伝熱・接触、公開鋳造実験です。

初期の暫定合格条件は、閉領域質量収支残差が流入出質量スケールに対して相対0.1%未満、Stefan前線位置相対誤差1%未満、AMR分割前後の保存量不連続なしを基準案とします。最終閾値は離散化、測定精度、顧客要求、物理モデルごとに承認します。

自由表面・AMRでは、総質量だけでなく流入出質量、液相・気相の扱い、AMR再分割時の液相体積、凝固時の液相と固相の密度を分けて評価します。質量収支は

\\[
M(t)-M(0)=\int_0^t(\dot M_{\mathrm{in}}-\dot M_{\mathrm{out}})dt+E_M(t)
\\]

として数値質量収支残差 \\(E_M(t)\\) を記録します。

決定論性は、同一GPU・同一環境でのビット単位再現性、異なるGPUでの数値的同等性、スキーム・コンパイラ変更後の数値回帰に分けて要求します。

各検証ケースには、入力条件、参照値、QoI、許容誤差、実験不確かさ、実行環境、バージョン、結果保存先を検証仕様として紐づけます。

| QoI              | 評価例                             |
| :--------------- | :--------------------------------- |
| 湯先到達時間     | センサー位置ごとの到達時刻差       |
| 充填形状・未充填 | 実験画像または参照解との界面位置差 |
| 温度履歴         | RMSE、最大誤差                     |
| 総質量収支       | 累積流入出質量と収支残差           |
| 欠陥位置         | 実測との位置・領域一致率           |
| 欠陥体積         | 絶対誤差・相対誤差                 |

校正用、検証用、未知条件評価用のケースを分離し、IHTC、気泡モデル、サロゲートの係数調整に使ったデータを精度評価へ再利用しません。OpenFOAM等の他ソルバー結果は相互比較参照であり、厳密解または実験Ground Truthではありません。

## 6. 製品化ロードマップ

### Phase 0：技術成立性検証

- 0-A：SyRS、Operating Envelope、参照解、QoI、検証ケース、採用基準を確定
- 0-B：均一格子でLBM系とGPU-FVM＋VOF系の比較プロトタイプを実行
- 0-C：代表的な自由表面、薄肉、ゲート形状、気泡・ベント候補でAccuracy、安定性、Time-to-Accuracyを評価
- 0-D：合格方式で静的AMRを検証し、保存則、解像度、性能、メモリを評価
- 0-E：対象GPUで最終的な採用・撤退判断、撤退時の代替方式を確定

LBM内部ではBGK/MRT/Cumulant/Entropic等をLevel 2候補として比較し、成熟したOSS実装は参照・相互比較系として利用してよい。

採用ゲートは必須項目と総合項目に分けます。

| 種別   | 基準                                                                                  |
| :----- | :------------------------------------------------------------------------------------ |
| 必須   | 指定した物理検証に合格、発散・不安定条件を許容範囲内で管理、対象GPUのVRAM内で実行可能 |
| 精度   | 同一QoI・参照解・実験不確かさに対する目標誤差を達成                                   |
| 性能   | 目標精度到達までの実行時間が比較方式を上回る、または承認した閾値を達成                |
| 拡張性 | 熱輸送、気相、凝固収縮、保持圧との統合負荷を許容                                      |

単純なMLUPSやセル更新数はカーネル最適化指標とし、方式選定はTime-to-Accuracyを主指標にします。合格方式が存在しない場合はOperating Envelopeを縮小するか、方式の追加・性能目標の変更を承認ゲートで判断します。

### Phase 1：RX-Flow Research Solver

- 選定済みGPU流体計算、自由表面、静的AMR、幾何入力、基本V&Vスイートを実装
- 完了条件：公開ベンチマークで再現性と数値誤差を定量評価できる

### Phase 2：RX-Flow Industrial Pilot

- 動的AMR、金型境界、射出プロファイル、気泡圧力モデル、基本熱輸送を追加
- 完了条件：顧客実験・工程データとの比較で予測精度と解析時間を確認できる
- 初期目標：高圧ダイカスト代表モデルを15分以内で完了し、既存手法との実測差を報告

### Phase 3：RX-Solid

- 凝固収縮、保持圧、熱応力、エアギャップ、GPU-CA、欠陥予測を段階的に追加
- 完了条件：個別物理と連成問題のCode/Solution VerificationおよびValidationを達成

### Phase 4：RX-Twin

- 自動パラメトリック実行、DoE、サロゲート学習、未知条件検出、設計環境連携を実装
- 完了条件：学習範囲を定義し、許容誤差と推論時間を実証

### 立ち上げ方針

すべてを最初から開発すると破綻するため、商用化までのロードマップでは一点突破を狙います。

1. **ターゲットを高圧ダイカストに絞る**
   メッシュ作成、超大規模セル、高速充填、複雑薄肉形状で既存ソルバーが苦手とするギガキャスト等に特化します。
2. **Phase 0の技術ゲートを通過後に流体ソルバーへ進む**
   技術選定を固定せず、検証済み方式を初期製品の核として提供します。
3. **Phase 2以降で連成、欠陥予測、リアルタイム設計へ拡張する**
   熱・凝固・応力・組織予測を統合した後、Physics-AIを段階的に加えます。

既存ベンダーは過去のコード資産、互換性、ライセンス体系によりフルGPU＋LBM＋AI統合への転換が難しい場合があります。RX-CASTはその隙間を、アルゴリズムから再設計した製品として狙います。
