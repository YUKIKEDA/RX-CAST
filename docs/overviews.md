# 次世代鋳造CAE「RX-CAST」構想・技術設計書

## 1. プロジェクト概要・ブランド定義

### 1.1 製品名とコンセプト
* **製品名：** **RX-CAST**（アールエックス・キャスト）
* **名称の由来（アクロニウム）：**
  **R**eal-time e**X**ascale **C**omputational **A**I **S**olidification **T**win
  （リアルタイム・エクサスケール対応のAI凝固デジタルツイン）
* **コアコンセプト：**
  **「完全ノーメッシング × GPUネイティブ爆速演算 × Physics-AI統合」**

### 1.2 ターゲット市場と初期突破口
* **メインターゲット：** 高圧ダイカスト（特にEVのギガキャスト等、大型かつ薄肉・複雑リブ形状の部品）
* **解決する課題：** 既存CAEで発生している「メッシュ作成の膨大な工数」「セル数爆発による計算時間の壁（数時間〜1日）」「設計案ごとの試行錯誤の遅さ」を根本から解消する。

### 1.3 モジュール構成
* **`RX-Flow`（湯流れエンジン）：** GPU-LBM＋Octree-AMRによる超高速湯流れ・空気巻き込みソルバー
* **`RX-Solid`（凝固・応力エンジン）：** 伝熱・凝固・熱応力（エアギャップ連成）・ミクロ結晶組織予測モジュール
* **`RX-Twin`（AI統合エンジン）：** 物理計算結果からリアルタイム予測モデル（0.1秒応答）を自動生成するPhysics-AIパイプライン

## 3. 物理モデリングと連成戦略

### 3.1 「完全強連成」を採らない技術的理由
物理現象すべてを単一の巨大行列で解く「完全強連成（Monolithic approach）」は理論上の理想ですが、以下の3つの壁により実用ソルバーでは破綻リスクが高くなります。
1. **時間スケールの極端な乖離：** 湯流れ（$\Delta t \sim 10^{-5}$ 秒）と凝固・冷却（$\Delta t \sim 1$ 秒以上）を同時に解くと、計算コストが爆発する。
2. **空間表現の衝突：** 流体に有利なオイラー格子と、変形に有利なラグランジュ格子の共存が困難。
3. **行列の条件数悪化：** 非線形性の強い流体・伝熱・接触弾塑性を混ぜると反復計算が収束しない。

### 3.2 RX-CASTの採用戦略：「フェーズ分割 ＋ 局所的陰的反復連成」
実用性と物理精度を両立するため、現象のフェーズに応じてソルバーを切り替える分離型（Partitioned）アプローチを採用します。

* **フェーズ1：充填期（湯流れメイン）**
  * **連成対象：** 流動（自由表面LBM） ＋ 対流伝熱（熱LBM）
  * **固液共存域の扱い：** 固相率 $f_s$ に応じて運動量損失を与える多孔質体近似（Carman-Kozeny式／ダルシー則）で流動停止を表現。応力変形は無視。
* **フェーズ2：凝固・冷却期（伝熱・変形メイン）**
  * **切り替え：** 充填完了後に流動計算をオフにし、時間刻み $\Delta t$ を大きく拡大。
  * **エアギャップの双方向連成：** 冷却収縮により鋳物と金型間に生じる「エアギャップ（界面熱伝達率 IHTC の急落）」は精度に直結するため、同一時間ステップ内で**「伝熱計算 $\rightarrow$ 応力・変位計算 $\rightarrow$ ギャップ幅からIHTC更新 $\rightarrow$ 熱再計算」**のサブ反復（Partitioned Two-way Coupling）を回して強連成と同等の精度を確保する。

## 4. 技術スタック・ソフトウェアアーキテクチャ

### 4.1 コアソルバー技術選定
* **開発言語・並列基盤：** C++20 ＋ CUDA（将来的なマルチGPUスケールのため NCCL / MPI 併用）
* **格子構造：** GPU最適化 **Octree-AMR**（溶湯界面と薄肉壁面付近のみ自動細分化し、メモリ消費を劇的に抑制）
* **湯流れ（`RX-Flow`）：** 自由表面モデル付き **LBM（格子ボルツマン法）** ＋ Immersed Boundary / Bounce-back 境界条件
* **伝熱・応力（`RX-Solid`）：**
  * 潜熱処理：エンタルピー法（Scheil-Gulliverモデル等による固相率変化を反映）
  * 構造・変形：巨大疎行列を作らず要素単位でGPUレジスタ上で反復する **Matrix-Free ボクセルFEM**
* **ミクロ組織予測：** マクロ格子内に細分化セルを持つ **GPU並列 CA（セルオートマトン）法**（柱状晶→等軸晶遷移：CETの直接予測）

### 4.2 Physics-AI ＆ システム基盤
* **サロゲートモデル生成（`RX-Twin`）：**
  * GPU爆速ソルバーを「教師データ生成器」として活用。夜間バッチでゲート位置・方案・射出条件を振った数百ケースを自動実行。
  * 得られた3D物理場データを **GNN（グラフニューラルネットワーク）** または **FNO（Fourier Neural Operator）** に学習させ、翌朝にはCAD変更に **0.1秒で追従するリアルタイム予測モデル** を提供。
* **ソフトウェア構成：**
  * **Headless Core & Python API First：** ソルバーはGUIから完全に分離したAPI/CLIバイナリとし、顧客の自動化・最適化パイプラインに容易に組み込める設計にする。
  * **モダン可視化：** プリ・ポスト処理には **WebGPU** 等を採用し、クラウド上のGPUサーバーで計算した数億セル規模の結果をブラウザ上で軽快に可視化。

## 5. 検証（V&V）用オープンデータセット・ベンチマーク計画

開発各段階の精度検証（Verification & Validation）には、以下のオープンな標準課題・実験データを利用します。

1. **アルゴリズム基礎検証（厳密解との比較）**
   * **ステファン問題（Stefan Problem）：** 1D/2Dの相変化・潜熱放出の解析解との一致確認。
   * **ダムブレイク / キャビティ自然対流凝固：** 自由表面挙動および溶融金属（Pb-Sn・ガリウム等）の流動＋凝固ベンチマーク（Gobinらのデータ等）。
   * **OpenFOAMチュートリアル比較：** `interFoam` や `solidificationMelting` をリファレンス実装として計算結果をクロスチェック。
2. **実測実験データとの妥当性確認（バリデーション）**
   * **MCWASP ベンチマーク：** アルミニウム平板等の湯流れ・湯面到達時間・引け巣実験データ。
   * **冷却曲線ベンチマーク：** 公開マニュアル・論文（Kronらの同心円筒鋳型実験など）の熱電対実測温度履歴との比較。
   * **放射光In-situ X線観察データ：** SPring-8、ESRF、Diamond Light Source等が公開するデンドライト成長・気泡挙動データ（CA法・欠陥予測モデルの検証）。
3. **熱物性・AI学習用リファレンス**
   * **OpenCALPHAD：** 合金組成からの状態図・液相線/固相線・Scheil固相率曲線の算出。
   * **NIST Materials Data Repository：** 金属の基礎熱物性値。
   * **Zenodo / Kaggle 公開データ：** ダイカストプロセス合成データセット（I-BiDaaS等）や鋳巣欠陥画像データ（AIパイプラインのプロトタイピング用）。

## 6. 開発・製品化ロードマップ

フルスペックを一度に開発するリスクを避け、以下の3段階で段階的に市場投入を行います。

* **Phase 1：MVP構築 ＆ 市場突破（`RX-Flow` 単体リリース）**
  * **開発内容：** GPU-LBM ＋ Octree-AMR による「ノーメッシング湯流れ・空気巻き込み解析」＋ 簡易熱LBM。
  * **目標体験：** 「既存ツールでメッシュ切りに半日・計算に一晩かかっていたギガキャストモデルが、STL投入から15分で終わる」状態を実現し、初期アーリーアダプターを獲得する。
* **Phase 2：連成・欠陥予測の完成（`RX-Solid` 統合）**
  * **開発内容：** フェーズ切り替え機構、エンタルピー法＋Matrix-Free ボクセルFEMによる熱応力・エアギャップ連成、およびGPU-CA法による組織・引け巣予測を追加。
* **Phase 3：リアルタイム設計革命（`RX-Twin` 完成）**
  * **開発内容：** 自動バッチパラメトリック実行エンジンとGNN/FNOサロゲート学習パイプラインを統合。設計現場に「0.1秒で結果が見えるAIデジタルツイン環境」を提供する。

---

### 1. コア計算基盤：完全GPUネイティブ設計
* **技術選定：C++20 ＋ CUDA（将来的なマルチGPUを見据えNCCL / MPI併用）**
* **選定理由：**
  * 従来の流体ソルバー（SIMPLE法や陰的FVM）は、巨大な疎行列方程式（圧力ポアソン方程式）を解く必要があり、GPUのメモリバンド幅と同期のオーバーヘッドで頭打ちになりやすいです。
  * 私なら、**「そもそもGPUのSIMT並列性能を100%引き出せる計算手法（局所演算・陽解法中心）」をアルゴリズム段階から選びます。** ワークステーション1台のハイエンドGPUで、従来のCPUクラスタ数十コア分の計算を数十分の一の時間で終わらせる設計にします。

---

### 2. 湯流れ・自由表面エンジン（フェーズ1）：GPU-LBM ＋ Octree-AMR
* **技術選定：自由表面モデル付き格子ボルツマン法（LBM）＋ 動的適合格子（Octree-AMR）**
* **なぜLBM（Lattice Boltzmann Method）なのか？**
  * 近年、産業界でもGPUとの親和性の高さからLBMが急速に実用化されています。LBMは「衝突（完全なセル内局所計算）」と「並進（隣接セルへのメモリコピー）」だけで構成され、圧力ポアソン方程式を解く必要がないため、**GPU上で桁違いの演算効率**を発揮します。
  * **ノーメッシング：** STLなどのCAD形状をそのままボクセル/Immersed Boundary（埋め込み境界）として扱えるため、ユーザーを悩ませる「メッシュ切り・形状修復」を実質ゼロにできます。
  * **Octree-AMRの併用：** ギガキャストのような大型・薄肉（1.5〜2mm）製品では均一格子だとセル数が数億に達します。そこで、**自由表面（湯先）と薄肉壁面付近だけ自動で格子を細かくする動的AMR（Adaptive Mesh Refinement）**をGPU上で走らせ、メモリ消費を抑えつつ精密な充填・巻き込み解析を実現します。
* *(代替案としてのSPH法)*
  * ダイカストの激しい飛沫や金型移動（プランジャーや中子移動）の表現に特化するなら**粒子法（SPH/MPS）**も有力な選択肢ですが、凝固収縮時の静水圧計算や熱境界の厳密な扱いに難が出やすいため、商用ソルバーとしての安定性・精度バランスを考えると **LBM-AMR** に軍配が上がります。

---

### 3. 伝熱・凝固・応力エンジン（フェーズ2）：ハイブリッド型
充填完了後は流れが止まるため、エンジンをシームレスに切り替えます。

* **伝熱・凝固：熱LBM（充填中） $\rightarrow$ 陽的/局所陰的エンタルピー法（冷却中）**
  * 充填中の対流伝熱は、LBMの二重分布関数モデル（Double Distribution Function）で速度場と温度場をGPU上で同時高速計算します。
  * 充填完了後は、時間刻みを大きく取るため、同じOctree構造のまま熱伝導＋エンタルピー法のモードに切り替えます。
* **熱応力・エアギャップ：Matrix-Free ボクセルFEM（またはMPM）**
  * 構造解析のためにわざわざ四面体メッシュを切らせるとユーザー体験が壊れます。そこで、流体・熱で使ったOctree/ボクセル構造をそのまま利用する**「Matrix-Free FEM（巨大行列を作らず要素単位でGPUレジスタ上で反復計算するFEM）」**あるいは **SPH-FEM連成**のようなハイブリッド手法 を採用し、エアギャップ（伝熱と変形の双方向連成）を高速に解きます。

---

### 4. ミクロ・欠陥予測の差別化：GPU並列 CA（セルオートマトン）法
* **技術選定：マクロ熱場に埋め込んだ GPU-CA（Cellular Automaton）法**
* **選定理由：**
  * 従来の「Niyama基準」などのマクロ指標だけでは、最新のアルミ合金や薄肉ダイカストの微細な欠陥・組織予測に限界があります。
  * 商用上位ソフト（ProCASTのCAFEモジュール等）でしかできない**「結晶粒成長（柱状晶→等軸晶遷移：CET）の直接予測」**は通常非常に重い計算ですが、セルオートマトン法はルールベースの局所演算であるため**GPU並列と極めて相性が良い**です。
  * 「速くて、ミクロ組織・機械的特性予測まで標準で出る」というのは競合に対する強力なキラー機能になります。

### 5. 最大のゲームチェンジャー：Physics-AI（サロゲートモデル）の統合
2026年以降の商用CAE市場において、単に「解析が数倍速い」だけでは、すでに顧客が持っている他社ソフトの置き換え動機になりにくいです。そこで、**「CAEソルバーをAIの教師データ生成器として統合する」**設計にします。

* **仕組み：**
  1. **自動デザイン探索（Headless Batch）：** ゲート位置、鋳造方案、射出速度などを自動でわずかに変えながら、GPU爆速ソルバーを一晩で数百ケース自動実行する。
  2. **オンデマンド・サロゲート学習：** 生成された数百ケースの3D結果（温度場、流速場、欠陥位置）を、組み込みの**GNN（グラフニューラルネットワーク）やFNO（Fourier Neural Operator）**に自動で学習させる。
  3. **リアルタイム設計：** 翌朝、設計者がCAD上でゲート形状や方案をドラッグして変更すると、**0.1秒で湯回りや引け巣のリスクがリアルタイムに可視化**される。
* 昨今の業界でも、MAGMAなどの解析結果を活用したサロゲートモデリングの検証が進んでいますが、**最初から「物理ソルバーとAI学習パイプラインが一体化した製品」**として提供できれば、設計現場のワークフローを根底から変えられます。

### 6. ソフトウェア構成・UX設計
* **完全ヘッドレス＆Python APIファースト：**
  * ソルバーコアは完全に独立したCLI/APIモジュールとし、GUIに依存させない。すべての操作（STL投入、条件設定、実行、結果抽出）をPythonスクリプトで記述できるようにし、顧客の自動化・最適化パイプラインに組み込みやすくします。
* **モダン可視化：**
  * プリ・ポスト処理のUIは、C++/Qtのような重厚長大なデスクトップアプリではなく、**WebGPU（または軽量なモダン3Dエンジン）**を採用し、クラウド上のGPUサーバーで計算した数億セルの結果を、手元のノートPCのブラウザ上でサクサク確認できるUXにします。

3. **Phase 2〜3で「熱・凝固・CA組織予測」および「AIリアルタイム設計機能」を順次統合**していく。

既存ベンダーが過去のコード資産の保守や互換性に縛られて「フルGPU＋LBM＋AI統合」へ舵を切りきれない隙を突くのが、技術的にもビジネス的にも最も勝率が高い戦略だと考えます。

### この比較表から見える「後発が勝つためのポイント」

既存のツールも、ADSTEFANのGPUモード やADPT（機械学習）、MAGMAの自律最適化 など、非常に優れた進化を遂げています。しかし、表を俯瞰すると明確な**「空白地帯（既存ツールのジレンマ）」**が見えてきます。

1. **「格子数爆発 × GPUメモリ」の壁を突破できるのはAMR-LBM**
   * 既存の直交格子ツール（MAGMA, ADSTEFAN, JSCASTなど）は「均一格子」または「シンプルな局所細分化」が基本であり、EVのギガキャスト（2m級の大型部品に厚さ1.5mmのリブが多数ある形状）を解こうとすると、**計算セル数が数億個に跳ね上がり、メモリも計算時間も破綻**します。
   * ここに対し、**動的Octree-AMR × LBM** を採用すれば、形状の複雑さに一切左右されず、高速かつメモリ効率よく解くことができます。

2. **「メッシュ切りゼロ」で応力・組織まで一気通貫**
   * 既存環境では「形状精度や応力を見たければProCAST（ただしメッシュ切りが大変）」「手軽にやりたければ直交格子系（ただし応力や曲面精度が犠牲）」というトレードオフが存在します。
   * ボクセル/Octree構造を共通基盤にして**Matrix-Free FEM**と**CA法**を乗せることで、ユーザーから「メッシュ作業」を完全に奪い去りながらハイエンドな物理（熱応力・結晶粒）を解けます。

3. **「CAEの実行結果」ではなく「リアルタイムAIモデル」を納品する発想**
   * 既存ツールの最適化（MAGMAのAutonomous Engineering 等）は「数十〜数百ケースを地道に回して最適解を1つ見つける」アプローチです。
   * 提案アーキテクチャでは、爆速GPUソルバーで一晩でデータを生成し、**翌朝にはCADを動かしながら0.1秒で結果が追従する「顧客専用AIサロゲートモデル」を生み出す**という、ワンランク上の体験で勝負できます。
