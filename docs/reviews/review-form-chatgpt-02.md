## **4. R2-01【P0】対象物理と適用範囲が未定義**

該当：1章、4章 RX-Flow、8章 要件・リスク・品質仕様

今回、最も優先したい指摘です。

8章で「対象合金、流速、形状、現象、精度、解析時間」を要求仕様に追加するとしていますが、実際の値や範囲はまだ存在しません。

数値解法の選定には、この情報が不可欠です。

例えば「高圧ダイカスト向け湯流れソルバー」でも、何を再現したいかによって要求が変わります。

| 現象        | 必要となるモデル・要件     |
| --------- | --------------- |
| 湯先到達時間    | 自由表面、壁面境界、射出条件  |
| 未充填・湯回り不良 | 自由表面、熱輸送、凝固     |
| 空気巻き込み    | 気相・ベント・気泡モデル    |
| 酸化膜巻き込み   | 界面履歴・酸化膜輸送モデル   |
| 凝固収縮      | 密度変化、給湯、保持圧     |
| ガスポロシティ   | 気体圧力、溶存ガス、核生成など |
| 金型変形      | 熱応力、接触、温度依存材料特性 |

これらを最初から一括で解こうとすると、Phase 0で比較すべき数値モデル自体が膨大になります。

### **修正案：適用領域をOperating Envelopeとして定義**

少なくとも以下を明記してください。

- **材料：** 初期対象合金と、その熱物性の温度依存範囲
- **幾何：** 鋳物最大寸法、最小肉厚、湯口寸法、最小流路
- **工程：** プランジャー速度・ゲート流速、射出温度、金型温度、保持圧履歴
- **現象：** 最初に再現する現象と、対象外とする現象
- **計算環境：** GPU機種、VRAM、許容メモリ、解析時間
- **精度：** 実験に対して何を何%以内で予測するか

具体的な値を実験データや文献に基づいて決めることが重要です。

例えば、最初の検証対象を「単一アルミ合金、固定金型、指定した射出プロファイル、湯先到達時間と未充填領域の予測」に絞るだけでも、技術選定が大幅に明確になります。

**判定：Phase 0開始前に必須です。**

## **5. R2-02【P0】保持圧の境界条件に物理的な問題**

該当：3章 フェーズ2、79行付近

現在の記述：

> 射出圧、保持圧、増圧履歴を境界または体積力として反映

「体積力として反映」という部分は修正を推奨します。

通常、保持圧・増圧圧力はプランジャー側から溶湯へ伝わる圧力であり、重力のような体積力と同一視できません。

例えば運動方程式は、

\\[ \rho \frac{D\mathbf{u}}{Dt} = -\nabla p +\nabla\cdot\boldsymbol{\tau} +\rho\mathbf{g} +\mathbf{f}\_{\mathrm{mushy}} \\]

のように表されます。

ここで、保持圧は一般に圧力境界条件やプランジャー運動・荷重条件によって与え、固液共存域の抵抗は別途 \\(\mathbf{f}\_{\mathrm{mushy}}\\) などで表現します。

両者を混同すると、保持圧が液相連結領域を通じてどう伝わるか、ゲート凝固後にどう遮断されるかを正しく表現できません。

実際、高圧ダイカストの給湯解析では、ゲートの凝固進行と圧力伝播が重要な要素として研究されています。

[image](https://www.google.com/s2/favicons?domain=https://www.mdpi.com\&sz=32)

MDPI+1



**推奨する修正文：**

> 射出・増圧・保持圧履歴は、プランジャーまたは流入口に対する圧力・速度・荷重境界条件として与える。固液共存域では透過率に基づく流動抵抗を考慮し、液相の連結性、ゲート凝固、および圧力伝播の変化を計算する。モデル簡略化のために等価体積力を使用する場合は、その導出、適用範囲、妥当性を別途検証する。

これならモデルが具体的になります。

## **6. R2-03【P0】Phase 0の選定ゲートが定性的すぎる**

該当：4章 RX-Flow、6章 Phase 0

今回、BGK、MRT、Cumulant、Entropic LBMとGPU-FVM＋VOFを比較する方針になりました。

しかし、現在の比較条件は「同一の高圧ダイカスト条件」という説明にとどまっています。

ここには二つの問題があります。

まず、BGK、MRT、Cumulant、Entropicは主としてLBM内部の衝突モデルに関する選択であり、GPU-FVM＋VOFは流体計算・界面追跡を含む別系統の方式です。

**比較の抽象度が異なっています。**

次に、同じ計算条件を使うだけでは、公平な性能比較になりません。

同じセル幅でも数値拡散や界面精度が異なるためです。

### **推奨：2段階の技術選定**

**Level 1：流体数値方式の比較**

LBM系 vs GPU-FVM系

**LBM系**

自由表面LBM＋境界・気相モデル

**GPU-FVM系**

圧力速度連成＋VOF

**Level 2：採用方式の内部最適化**

衝突モデル・界面処理・AMR・メモリ配置・GPU性能

比較基準としては、以下を提案します。

| 評価軸      | 測定内容               |
| -------- | ------------------ |
| 正確性      | 共通QoIの実験値・解析解との差   |
| 数値安定性    | 発散条件、許容CFL/Ma、残差履歴 |
| 計算速度     | 同等精度を達成するまでの実行時間   |
| メモリ      | 最大GPUメモリ、セル当たり使用量  |
| スケーラビリティ | セル数増加に対する処理性能      |
| 複雑形状適性   | 薄肉、ゲート、曲面境界の再現性    |
| 拡張性      | 熱輸送、気相、凝固モデルとの統合性  |

特に採用するべき指標は、\*\*Time-to-Accuracy（目標精度に到達するまでの計算時間）\*\*です。

単純なMLUPS（Million Lattice Updates Per Second）やセル更新数は、カーネル最適化には有用ですが、異なる数値方式の製品性能を比較する指標としては不十分です。

### **採用判定の例**

「必須の物理検証に合格する」「対象GPUのメモリ内で実行できる」「同等精度での時間が比較対象より短い」などを、必須条件として固定します。

その後、合格した方式だけを総合評価します。

合格方式が存在しなければ、対象問題の縮小、性能目標の修正、別方式の追加を行うべきです。

## **7. R2-04【P1】流動停止の局所判定に注意**

該当：3章 フェーズ3、84～85行

修正版では、液相率、圧力勾配、残留速度、連結液相領域に基づいて、領域ごとに流動を停止するとしています。

これは前回より適切ですが、次の問題が残ります。

**速度が小さいことは、その領域で流動計算を停止してよいことを意味しません。**

現在の速度がゼロでも、後から圧力勾配や温度勾配が発生すれば流動が再開する場合があります。

また、液相の連結性が変化すると、給湯可能な経路が変化します。

そのため、局所的な閾値判定だけで流動解法を無効化すると、質量保存や圧力伝播が不連続になる危険があります。

### **推奨**

解法の切り替えは、単独セルではなく**連結領域または計算ブロック単位**で管理することを推奨します。

例えば、以下の状態遷移です。

**Active Flow**

流動＋熱＋凝固

**Reduced Flow**

給湯・圧力伝播を維持する縮約モデル

**Thermal Only**

熱・凝固計算、必要に応じ応力解析

実装上は、再活性化条件、状態遷移時の保存量の引き継ぎ、閾値付近での頻繁な切り替えを避けるヒステリシスが必要です。

そもそも流動停止による高速化が小さい場合は、この仕組み自体を採用しない選択肢も残すべきです。

## **8. R2-05【P1】自由表面・気相モデルの選択がまだ不足**

該当：4章 RX-Flow、112～118行

気泡の圧縮・分裂・合体、ベント・真空条件が追加されたことは適切です。

ただし、これらは個別機能の列挙であり、連続体モデルとしてどう扱うかが定まっていません。

検討すべきモデルは主に次の3種類です。

| モデル         | 特徴                   | 適用候補        |
| ----------- | -------------------- | ----------- |
| 単相流＋自由表面    | 気相を明示的には解かない         | 初期の湯回り解析    |
| 単相流＋気泡モデル   | 閉じ込めた気体を圧力・体積関係などで扱う | 簡易空気巻き込み    |
| 圧縮性気相を含む二相流 | 気相の圧力・流速・密度変化を解く     | 高度な気相・ベント解析 |

特に、ダイカストでは排気経路、気泡の圧縮、ゲート通過時の高速流動が重要になります。

2026年に発表された圧縮性多相流によるダイカスト解析研究でも、気相巻き込みとCT計測との照合は行われていますが、増圧時の圧力伝播や凝固収縮を含む統合的な予測には課題が残っています。

スプリンガーリンク



したがって、Phase 0では**最終的に必要な気相モデルが、選定する流体方式と両立するか**を技術選定の条件に追加すべきです。

単相流で良い成績を収めた方式が、後から気相モデルを追加した場合にも最適とは限りません。

## **9. R2-06【P1】AMRと時間積分を別々に評価しない**

該当：4章 106、114、120行付近

静的AMRから動的AMRへ拡張する方針は妥当です。

ただし、LBMとFVMでは、粗細格子間の処理と時間積分が異なります。

特に重要なのは次の3点です。

**① 解像度だけではなく時間刻みが変化する**

AMRの細かいセルが全体の時間刻みを制限すると、セル数を減らしても速度向上が限定的になる可能性があります。

**② 保存則が重要**

LBMでは分布関数の補間・再構築、FVMでは粗細格子間の流束整合・補正など、方式ごとの保存則維持が必要です。

**③ GPUの負荷分散**

動的AMRでは、細かいセルが局所的に集中すると、GPUの実行効率やブロックごとの負荷バランスが悪化する場合があります。

AMRの性能評価は、次のように分けると良いでしょう。

\\[ T\_{\mathrm{total}} = T\_{\mathrm{solve}} + T\_{\mathrm{adapt}} + T\_{\mathrm{transfer}} + T\_{\mathrm{communication}} + T\_{\mathrm{I/O}} \\]

このような内訳で、均一格子、静的AMR、動的AMRを比較します。

さらに、薄肉部品では**壁近傍と狭い流路の幾何学的解像度**が重要です。

最小肉厚1.5～2mmを対象とするなら、何セルで肉厚を解像するか、壁面近傍の精度をどう保証するかを要求仕様に追加してください。

AMRで自由表面だけを細分化しても、湯口や薄肉流路を十分に解像できなければ目的を達成できません。

## **10. R2-07【P1】V&Vは改善したが、定量評価の仕様が不足**

該当：5章 269～282行

Verification、Validation、UQを分けたことは適切です。

ただし、現在の暫定合格条件にはいくつかの問題があります。

### **10.1 保存則の相対誤差0.1%だけでは不十分**

自由表面、AMR、境界流入出がある解析では、単純な総質量の相対誤差だけでは判定できません。

例えば質量収支は、

\\[ M(t)-M(0) = \int_0^t \left(\dot M\_{\mathrm{in}}-\dot M\_{\mathrm{out}}\right)\\,dt + E_M(t) \\]

と書けます。

ここで \\(E_M(t)\\) が数値的な質量収支残差です。

評価には、総質量だけでなく、流入出質量、気相・液相の扱い、AMR再分割による変化を含める必要があります。

さらに、液相・固相で密度が異なる凝固解析では、液相体積と総質量を区別して評価すべきです。

### **10.2 決定論性と数値再現性を分ける**

「同一条件での決定論的再現」を基準案としていますが、GPU並列計算では演算順序による浮動小数点差異が発生し得ます。

したがって、

- 同一GPU・同一実行環境でのビット単位再現性
- 異なるGPUでの数値的同等性
- スキームやコンパイラ変更後の数値回帰

を別の要求として扱うことを推奨します。

### **10.3 V&Vの評価量を明確にする**

例えば湯流れ解析であれば、以下のような評価量（QoI：Quantity of Interest）を指定できます。

| QoI    | 評価例          |
| ------ | ------------ |
| 湯先到達時間 | センサー位置ごとの時間差 |
| 充填形状   | 実験画像との界面位置差  |
| 温度履歴   | RMSE、最大誤差    |
| 総質量収支  | 累積収支誤差       |
| 欠陥位置   | 実測との位置・領域一致率 |
| 欠陥体積   | 絶対誤差、相対誤差    |

ASME V&V 20も、指定した評価量・検証点における数値解と実験データの比較、およびそれぞれの不確かさを重視しています。

[image](https://www.google.com/s2/favicons?domain=https://www.asme.org\&sz=32)

ASME



**提案：** 各検証ケースを単なる名前ではなく、入力条件、参照値、評価量、許容誤差、実行環境、結果保存先を持つ「検証仕様」として管理してください。

### **10.4 文書内の小さな矛盾**

5.4節ではOpenFOAMのテストケースを「Ground Truthまたは相互比較リファレンス」としていますが、直後の文章では実験Ground Truthではないと説明しています。

ここは「相互比較リファレンス」に統一してください。

## **11. R2-08【P1】凝固収縮・欠陥予測がまだ抽象的**

該当：4章 RX-Solid、136～145行

現在、欠陥予測としてNiyama等の指標を補完する構想になっています。

しかし、高圧ダイカストの欠陥には異なる発生機構があり、単一の欠陥指標で扱えるとは限りません。

| 欠陥          | 必要となるモデル       |
| ----------- | -------------- |
| 収縮ポロシティ     | 凝固収縮、給湯、圧力伝播   |
| ガスポロシティ     | 気泡、圧縮、溶存ガスなど   |
| 湯境・コールドシャット | 湯先温度、合流履歴、酸化状態 |
| 酸化膜巻き込み     | 自由表面履歴、界面の折り込み |
| 熱間割れ        | 凝固組織、ひずみ、給湯、応力 |

特に、収縮ポロシティとガスポロシティは分けて設計した方がよいです。

例えば、凝固収縮を考慮する場合、密度変化や液相・固相の相変化によって質量保存式の扱いが変わります。

また、Scheil-Gulliverモデルを採用する場合は、適用する合金系、平衡状態図との関係、拡散の仮定、固相率曲線とエンタルピーの整合性が必要です。

**提案：** RX-Solidの内部機能を「Thermal/Solidification」「Feeding/Shrinkage」「Defects」「Microstructure」「Mechanics」に分離し、検証可能な単位で段階的に開発することを推奨します。

## **12. R2-09【P1】Phase 0はさらに絞るべき**

## **14. 次に実施すべきこと**

今回の改訂で、アーキテクチャを再度大きく変更する必要性は低くなりました。

次に必要なのは設計書をさらに長くすることではなく、**意思決定に必要な仕様を独立した文書として確定すること**です。

推奨順序は以下です。

**1. System Requirements Specification（SyRS）**

対象物理、材料、計算領域、性能要求、GPU環境、除外事項を定義する。

**2. Numerical Methods Evaluation Plan**

LBM/FVMの比較ケース、共通QoI、採用基準、ベンチマーク手順を確定する。

**3. V&V Plan**

検証ケース、参照解、数値誤差、実験不確かさ、合格基準を定義する。

**4. Software Architecture Specification**

モジュール境界、Field API、GPUメモリ管理、スケジューラ、データ形式を定義する。

これらはすべて一度に完成させる必要はありません。まずSyRSと数値方式の評価計画を決めれば、Phase 0の実装を具体化できます。

## **15. 最終判定**

## **条件付き承認**

構想設計として

**製品構想・基本アーキテクチャについては、次段階へ進めてよい水準になっています。**

一方、数値ソルバーの本格実装に対しては、P0の3項目が残っているため、まだ承認できません。

前回と比較すると、最も大きな進歩は、LBMやAMRを「使いたい技術」から「採用根拠を検証する技術」へ変更したことです。

これは数値解析ソフトウェアを開発する上で重要な設計判断です。

今回の改訂に対して、私が特に強調したいのは次の点です。

**RX-CASTが今決めるべきなのは、どの数値アルゴリズムを実装するかではなく、どの鋳造現象を、どの精度・時間・ハードウェア制約で計算する必要があるかです。**

その要求が定まれば、LBM、FVM、AMR、気相モデル、連成方式の採用判断に一貫した根拠が生まれます。

したがって次の作業としては、構想書そのものの再改訂よりも、**Phase 0用の数値要求仕様書と技術選定・検証計画書の作成**を最優先に推奨します。
